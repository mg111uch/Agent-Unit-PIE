## Features Overview

| Capability | Description |
|------------|-------------|
| Hot-Reload | Auto-detect tool module file changes and reload without restart; explicit `kernel_reload` and `hot_reload` tools |
| Roadmap–Gap Linking | `scripts/link_gap_blockers.py` links `known_gap` hypotheses to near-term roadmap bullets with `requires` / `required_by` edges (idempotent ids, `--dry-run`); queryable via `get_neighbors` |
| Hypothesis → Semantic Memory Export | `export_to_semantic_memory` uses hypothesis_type as node_type (`capability_claim` / `known_gap`) and stores `status` in metadata; validated capabilities + gaps searchable via `search_semantic_memory` |
| `dev_change` Events | `dev_change` event type (`development` category) emitted via `EventEngine.create_event` / `scripts/emit_dev_change.py` and the `kernel_emit_dev_change` agent tool; `timeline_engine.add_event` records summary + paths in the timeline |
| Citation Cache | `citation_cache` table (path+symbol+mtime keyed); `validate_capabilities` re-resolves citations only when cited paths change, else marks "cached (mtime unchanged)" |
| Status from Events | `scripts/render_recent_changes.py` drives status Recent Changes from the last 10 `dev_change` events (hybrid: event bullets + uncovered manual bullets, cap 10); newest-first, idempotent |
| Status Regeneration | `scripts/render_status.py` regenerates Current Capability / Known Gaps / Recent Changes from `capability_claim` + `known_gap` hypotheses and `dev_change` events, preserving other sections; `_Last verified` header preserved |
| Generated Capability Sections | Status capability sections carry a generated-cache marker (`> Capability section generated by scripts/render_status.py`); `render_status --write` is idempotent on all 5 status files and passes `report_schema_check_tool` |
| Removal Rationale Log | `scripts/record_removal.py` records `side=decision` nodes + `contradicts` edges for `project_history` via kernel semantic memory (idempotent, `--dry-run`/`--json`; `graph.json` is a regenerated view); contradicts edges between agreed beliefs emit a kernel `contradiction_detected` signal; `validate_capabilities` FAIL detail suggests the exact `record_removal` command |
| Topic-Graph Kernel Store | `argu_god/engine/topic_store.py` is the single writer/reader for topic data (SQLite canonical, hydration on boot); generic CLI `scripts/topic_ops.py` (add-node/add-edge/list) + backfill via `scripts/backfill_topics.py`; user manual in `usage.md` |
| Per-Simulator Registry | `kernel/simulator_registry.py` discovers `codebase/modules/simulators/*` (`popula_dyn`→`popu_sim`, `eco_sim`→`sim_eco_sim`); strict isolation: findings, topics, and lineage scoped per simulator |
| Simulation Lineage (Git-backed) | `kernel/simulation_version.py` + `kernel/git_version.py` + `simulation_schema.py:130` + `simulation_versions`/`simulation_runs` tables; `sync_from_git(sim)` maps Git commit scoped to `simulators/<sim>` → `sim@commit` (`sim_commit`, `diff_sim_files`), fallback `V1_hash`; prevents `virtual_silicon` commits from bumping `popula_dyn`; concepts via ontology-aware `_load_ontology_concepts()` (see below) |
| Sharded Simulations & Episodic | `modules/simulators/simulation_connector.py:44` shards FS `data/units/simulations/{sim}/{run}` (+ legacy `codebase/units/simulations` fallback/migration), persists `simulation_runs` (per-sim) and `episodic_memory` + `data/memory/episodic/{sim}_{run}.json` (immutable raw) |
| Validity Scope | `kernel/validity.py:13` concept-level `ACTIVE→HISTORICAL` per-sim (`affected_by` via ontology-aware `_load_ontology_concepts`); skips `consolidated_observation` (rebuilt via materialized view); `sync_from_git` auto-marks stale raw findings `invalidated_by` then triggers `recompute_consolidated` (e.g., `reproduction` → 3/3 population HISTORICAL, `terrain` → 0/3) |
| Version-Aware Retrieval | `kernel/retrieval/retrieval_engine.py:75` + `semantic_retriever.py:139` filter `simulator` + `HISTORICAL` + `is_compatible(find_ver, query_ver, sim)`; default `include_historical=False` (audit `True`); episodic also per-sim; consolidated `HISTORICAL` auto-excluded |
| Symbolic Contradiction Gate | `kernel/hypothesis/contradiction_gate.py:67` per-sim version-aware: `_compatible_for_contradiction` skips cross-sim / HISTORICAL / incompatible versions, symbolic `INCREASE vs DECREASE` only within same `sim`+compatible lineage; cross-sim never contradicts |
| Per-Sim Compression (Materialized View) | `kernel/compression_engine.py:147` groups `ACTIVE` raw findings per `(sim, outcome, horizon//10)` → `consolidated_{sim}_{outcome}_{bucket}` (`consolidated_observation`) carrying `simulator, source_findings[], source_versions[], affected_concepts[], validity{ACTIVE@cur_ver}, derived_at`; excludes self-grouping; `recompute_consolidated(sim)` rebuilds from remaining ACTIVE (`<2` → `HISTORICAL`, else recomputed `avg_delta`) after invalidation; episodic raw stays immutable |
| Declarative Simulation Ontology | `codebase/modules/simulators/popula_dyn/ontology.yaml:1` + `kernel/schemas/simulation_schema.py:130` `_load_ontology_concepts()`/`concepts_for_changed_files()` merges per-sim `ontology.yaml` (`modules: {reproduction: {concepts:[..], outputs:[..]}}`) over fallback `MODULE_CONCEPTS`; simulator declares its own semantic impact, no hardcoded mapping required |
| Unified Development Loop | `data/workflows/research_development.json:1` (12-node contract `start→orient→version_sync→hypothesis→decide_branch→{experiment,modify_code}→update_knowledge→evaluate→validate→loop→stop`, meta `subgraphs:[kernel_ops,popu_sim_dev]`); `development/workflow_engine.py:34` `UNIFIED_NODES` + `load_json/allowed()/advance(target,produced,success)` enforces `allowed` + `success∈node.success` + `outputs` present; prevents `start→experiment` skip; `development/contracts.py:12` validates `id,goal,outputs,success,next` + legacy array compat |
| DevelopmentState | `development/development_state.py:70` `generate_state(sim)` merges `git_version(sim_commit/current_commit) + simulation_version(sim@commit/aff_concepts) + workflow_engine(allowed/wf_node) + hypothesis_engine(hyps/gaps) + simulation_runs(recent)` into `<1.9KB` `{sim,git,sim_commit,sim_version,aff_concepts,wf_ver,wf_node,allowed,hyps,gaps,runs,ts,_bytes}` with trim; `state_text()` renders `CURRENT STATE ... ALLOWED: ...` |
| develop.* Primitives | `development/develop_tools.py:211` 9 `CAT_DEVELOP` tools (`develop_state/orient/experiment/analyze/modify_simulator/modify_workflow/modify_kernel/validate/commit`) — each composes deterministic ops (`retrieval_engine.search`, `SimulationConnector.run_and_extract+register_to_kernel`, `CompressionEngine.compress_observations`, `git_commit`) and advances `workflow_engine`; hides `conda run ... topic_ops.py` shell; `develop_modify_*` gated via `validation_gate` |
| Graduated Autonomy Gate | `development/validation_gate.py:11` `LEVELS L0 suggest /L1 edit+test /L2 edit+test+commit /L3 sim_modify /L4 workflow_modify /L5 kernel_propose /L6 kernel_modify` (`DEFAULT_CEILING=3` sim autonomous, L4+ gated, L5-6 human approval); `required_level(path)` (`simulators/*→3`, `data/workflows→4`, `kernel→6`); `gate(level,path,human_approved)` runs `contracts,sim_smoke,lineage,retrieval,workflow_conformance,human_approval` and blocks `L3 kernel`/`L1 workflow`/`L6 without approval` |
| Agent Evaluation Harness | `development/eval_harness.py:14` `run_all()` harness (FixesIssues 6A/B/E/F + 9): `workflow_conformance` (legal `orient→…→update_knowledge` + illegal `start→experiment` blocked), `recovery` (missing params → Error), `adversarial_lineage` (5 invariants `V1 stale/partial/unrelated/no-contradiction/same-version`), `workflow_evolution` (added node still validates), `research_loop` (`_bytes<2000`); helpers `conformance_mini`/`adversarial_mini` reused by gate |
| Agent Onboarding | `codebase/prompt_fragments/onboarding.md` (in `FRAGMENT_ORDER`) points agents at `project_history` + `list_capabilities`/`report_inventory` instead of full-report reads |
| Capability Regression Signal | `validate_capabilities` detects regressions (previously-`supported` caps now FAIL, via citation_cache) and emits a `capability_regression` kernel signal |
| Tool-Bypass Detection | `scripts/detect_tool_bypass.py` surfaces repeated raw Reads on atlas-indexed files via `pattern_engine.detect_repeated_events` |
| Project Health Index | `scripts/render_index.py` writes a `generated_reports/INDEX.md` health badge from report inventory + schema check + capability validation |
