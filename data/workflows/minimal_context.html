⏱ Patterns to Avoid (Token Waste)

  • AVOID Reading full non-kernel files with Read when pie_file_api already reveals structure. Only Read after you know the exact lines needed. In this session, reading server/__init__.py and ws_handler.py in full cost ~900 lines of context.
  • AVOID Sequential pie_file_api calls for 2+ files. Use one pie_file_api with paths=[...] — it does the same work in one round trip.
  • AVOID Fetching source without checking metadata first. Always call pie_get_symbols_meta before pie_get_symbol. A 200-token symbol may not be worth including.
  • AVOID Listing too many starting symbols — blast radius doubles or triples the count. For minimal_context_dump, 5-8 focused symbols yield a tighter dump than 13+ broad ones.
  • AVOID Multiple budget iterations. Estimate upfront: context_dump.py uses len//4 as token estimate. Mean symbol size from pie_get_index_info × expected blast radius × 3 (for overhead) → set max_tokens to that × 1.5.
  • AVOID Using full class.method() as symbol name (e.g. GeminiProvider.generate instead of GeminiProvider). The atlas indexes the class, not individual method paths.
  • AVOID Regenerating atlas without checking first. Use pie_atlas_status + pie_get_symbol to verify the symbol is actually missing before running a full reindex (~30s).

✅ Patterns to Follow

  • DO CALIBRATE → ORIENT → META → FETCH → TRACE in that order. Every skip costs tokens later.
  • DO Use pie_report_freshness at session start to decide whether to trust status.md claims or re-verify.
  • DO Batch symbol lookup — pass multiple names in one pie_get_symbol(names=[...]) call. One network round trip vs N.
  • DO Append analysis to the context file after generation. The external LLM benefits from seeing both source code and the issue taxonomy in one file.
  • DO Set max_tokens = 3 × estimated need on first attempt to avoid re-running. Tokens are cheap; round trips are not.

🛠 New Tools That Would Accelerate This

  • TOOL pie_estimate_dump_cost(symbols, files) — Dry-run the blast radius expansion and token estimate without writing anything. Returns: total symbols in blast, estimated tokens, suggested max_tokens. This would eliminate the guess-and-retry loop entirely.
  • TOOL pie_reindex_symbols(names=[...]) — Targeted atlas reindexing for specific files/symbols. Today, a single missing symbol forces a full regeneration of all 55 files. Per-file reindex would take seconds, not 30+.
  • TOOL pie_find_common_issues(path) — Static analysis pass over agent_core code: flags functions >400 lines, duplicate code blocks, missing error handling, bare excepts, circular import risks, interface inconsistencies. This would auto-discover issues #6, #7, #8, #11, #12, #16 from this session.
  • TOOL pie_diff_from_atlas(symbol_name) — Shows diff between current on-disk source and last indexed version. Helps decide whether a full reindex is needed vs the atlas being acceptably fresh.
  • TOOL pie_symbol_dependency_graph(symbols, depth) — Previews the call graph neighbors for a set of symbols before running the full context dump. Returns: total reachable symbols, file spread, estimated token cost at each depth level.

♻ Generalized Workflow (Any Issue)

The same 6-phase workflow applies to any issue:

  1. SCOPE — Read the task, check reports, identify the module boundary.
  2. EXPLORE — Orient with file_api/symbols_by_file, metadata with get_symbols_meta.
  3. ANALYZE — Fetch source for ~5-8 critical symbols, read non-kernel files only where needed.
  4. PACKAGE — Collect symbol names + peripheral file paths. Verify atlas freshness.
  5. GENERATE — Run minimal_context_dump with generous max_tokens. Check for warnings.
  6. ENRICH — Append findings, suggestions, priority. Verify final file completeness.
